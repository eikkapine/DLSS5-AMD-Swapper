# DLSS5 AMD Swapper v0.3.0-pre.4

This preview adds AMD-NR pre-SR packages, fixes Restore after a game has been played, and carries the bridge fixes that issue #3 needs for a retest.

- The OptiScaler pre-SR route accepts [AMD-NR](https://github.com/3zwr1/AMD-NR---OptiScaler) packages with their matching Runtime zip extracted into the same folder. The fork is identified by its build string, pass DLLs and weights are found beside `OptiScaler.dll` or under `Runtime\`, and the package's `Runtime/` checksums are enforced, so a fork mixed with passes from another runtime release is rejected before anything is copied. The optional lmxxf runtime is installed and restored with the rest.
- Restore deletes `dlssnr_on_amd.log`, `OptiScaler.log`, `amd_presr.log` and `lmxxf_backend.log` unless they existed before the install. Every launch rewrites them, so Restore used to keep them as changed files together with the manifest, which left the game marked as managed and blocked switching routes.
- **Settings → Check runtime updates** also checks AMD-NR releases. Latest AMD-NR release checked: Alpha0.3.1.
- The bridge no longer aborts a healthy DLSS-NR-on-AMD v0.3.1 startup because the runtime's informational DRED notice contains the word `fault`. Its HIP instrumentation now follows whichever HIP imports the runtime uses, including v0.3.1's stream and event waits, instead of disabling the whole trace when one import is missing (issue #3).
- Game discovery also scans Xbox libraries named `<drive>\Xbox`, not only `<drive>\XboxGames`.
- A detected anti-cheat can be waived per game after a warning that names the ban risk. The waiver is saved per executable, shown in the game list and reversible; the x64, FSR and DX12 checks still apply.

Download and extract the portable ZIP, then run `Dlss5AmdSwapper.exe` or `Install.cmd`. The bridge changed in this release: close Lossless Scaling and run its setup/update in the new manager to deploy it. Updating only the manager does not replace an installed bridge. External runtimes, OptiScaler forks and proprietary neural files remain user-supplied and are not bundled.

Validation: C# smoke/regression suite, 54 Python tests, native bridge CPU tests, auto-scale harness and four installer configurations, 15 packaging/rollback tests, five desktop lifecycle processes, 1,899 theme/contrast checks, and self-contained package checksum verification. The published AMD-NR Alpha0.3.1 fork and Runtime files were validated in scratch folders, including rejection of a pass DLL from an older runtime release.

No GPU performance benchmark or in-game neural run was performed for this release. AMD-NR has not been launched in a game here, and issue #3 still needs a retest on the affected machine with this build.

See [AMD ecosystem refresh](https://github.com/eikkapine/DLSS5-AMD-Swapper/blob/v0.3.0-pre.4/docs/amd-ecosystem-20260924.md).
